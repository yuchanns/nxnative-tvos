# Persona 5 Royal optimization notes

The target is an A12 Apple TV with about 3 GB of memory. Rendering ended at native 1920x1080 with 3840x2160 display output. BC-to-ASTC conversion retained texture dimensions but is not a claim of bitwise lossless original-format rendering.

The principal changes were general NVN/Metal semantic and ownership fixes. Upstream native execution, Horizon services, shader translation and earlier shared tvOS optimizations are prerequisites, not inventions of this P5 effort.

| Work | Mechanism and invariant | Evidence and limit |
| --- | --- | --- |
| Visibility batching | Accumulate queries until a real consumer/barrier; allow redundant pool state and `RAST_DISCARD=0` across pending results; preserve discard-on and true dependency flushes. | Same casino: render encoders 234.92→50, compute 223.92→40, resolves 187.92→4 per frame, query count retained; approximately 18.2→30 fps. |
| Color attachment lookahead | Stop when actual bound RT needs are known, rather than waiting for all eight possible slots. | Fixes a locally introduced CPU scanning regression; 256 masks plus boundaries; no isolated whole-game gain claimed. |
| Unused depth attachments | Omit only when depth/stencil/clear and subsequent draws prove no use; include ALWAYS/no-write. | Corrected an off-by-one pass association before deployment. An earlier casino attribution was withdrawn. |
| Lazy ShaderWrite | Eligible color RTs initially request only needed usage, preserving compression eligibility. Upgrade and copy all subresources on actual image access; replace aliases and retire old objects after fences. | Same battle: 24.1–24.5 fps / GPU 37.58 ms before; 26.6–27.1 / 33.845 ms after; a subsequent run retained 26.7–27.1 / 33.62 ms. |
| Bounded pool views | Use range-checked no-copy windows instead of exposing entire 650/672 MiB pools to Metal; unknown lengths retain conservative fallback. | Removes a source of excessive residency; logical range bytes are not physical memory saved. |
| Commit-order dependency | Bridge actual submission order rather than assuming command-buffer creation order establishes dependencies. | Correctness constraint for scoped upload windows; never delete required synchronization. |
| Upload ownership | One-shot source buffers survive through GPU completion only; idle persistent windows retire with every address/argument/binding cache invalidated. | Station slowdown trace: 11,216 file page-ins over 6.536 s, main-thread waiting intervals 5.832 s; repeated page-ins demonstrate working-set churn. |
| CPU/GPU address separation | CPU hashes use bounded CPU lookup; query writes use 16-byte ranges; BC copies use actual region spans. | Two same-process unprofiled resumes no longer reproduced prior 2.405 s stall; residual ~0.2 s pauses remain. |
| Texture snapshots | Fence-complete idle resources are saved exactly in bounded 4 MiB steps, purged only after complete success and restored before consumption; cancellation/failure retains authoritative content. | Pressure hysteresis, small textures and idle retirement added. Special resources retain separate ownership rules. |
| BC authoritative buffers | Weakly track original BC buffers retained through texture aliases; snapshot after 120 idle frames, restore via every CPU/GPU/raw-view access. | Corrects an ownership class missed by the earlier texture-only inventory; no isolated MB-saving claim. |
| Temporary retention | Scope restore staging, weak shader-to-arena references, fence-safe idle shrinking of argument arenas/upload slots/zero buffers. | Repeated restore and failure tests cover staging growth; metadata and PSO caches are not asserted permanently bounded. |
| Offline ASTC and diagnostics | Content-addressed preconversion, verified cache reads and atomic writes; instrument exact misses and errors, extend 75,366→84,353 keys without renaming old chunks. | More coverage helped, but did not explain every miss. Cache completeness and absence of unnecessary work are separate questions. |
| Defer overwritten initialization | Preserve original BC blocks while postponing initial conversion on copy destinations; convert untouched planes only if later read. | Same cold load: 2,555 unnecessary initial conversions avoided, 2,564 actual copies hit cache, zero live encodes; old 1.08 s upload stall absent in that window. |
| Trace-driven PSO warmup | Expand manifest 1,090→5,227 descriptors and verify keys; move synchronous creation away from first battle/attack. | New unseen content can still miss. |
| BC copy batching | Gather up to 64 consecutive destination planes; one synchronization per batch; flush at consumers, barriers, target changes or list end. | Device selftest 8,095 checks, including 4 copies→1 sync. Differing transition routes prevent a whole-load percentage claim. |
| Resource distribution | Real file fragmentation, fragment/chunk hashes, fsync and inode-bound receipts; four download slots retained through serial extraction and receipt commit. | Bounds queued archives and resumes valid cached work; not a rendering optimization. |
| Complete shader gate | Check keys, base/variant libraries, reflection, bindings and target proof independently of process exit status. | 30,646 keys and 27,501 variants; catches partial builds that returned success. |
| Reliability | NV12 UV stride, LINEAR_RENDER_TARGET, Metal3 clears, SIGPIPE handling, callback-before-commit ordering, recoverable listeners and lifecycle tracing. | Separate historical causes: build16 memory limit SIGPIPE introduced Metal callback assertion. |
| Low-overhead observation | Publish renderer-owned snapshots to HTTP; fixed-interval memory sampling; delayed screenshots; merge rotated logs by process identity. | Prevents diagnostics, old PIDs, overlapping GPU intervals and logical allocation totals from contaminating conclusions. |

Vertex/fragment overlap showed no stable significant gain. Read-only vertex dependency refinement changed median GPU time only about 37.99→37.58 ms. Neither is presented as the main success. Simply enabling pass batching, enlarging ASTC coverage, or lowering reclamation thresholds did not solve the respective semantic/ownership problems.

The final window retained 899 samples over approximately 75 minutes, maximum gap 5.029 s, sampled footprint peak 0.864 GiB and final 0.677 GiB, without pressure/background/exit events. Five-second sampling cannot bound shorter peaks. Thousands of real texture and BC restores occurred. Earlier >1 s frames remain in the record; this is not an all-game 30-fps or zero-stall claim. HDMI physical AV synchronization and exhaustive repeated-route convergence were not independently measured.

For the next title, first freeze identity and acceptance scenes; classify steady GPU/CPU cost, compilation, upload, synchronization, paging, and lifecycle failures separately. Audit all resource owners, recovery sources, fence lifetimes and alias invalidation before reclaiming anything. Treat thresholds as policy parameters, not correctness arguments. Prove exact restoration and failure handling in CPU tests, then use same-scene device comparisons and long-duration observations independently.
